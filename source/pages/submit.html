Open a pull request

Put the files under the proposed paths inside one folder, here my_submission, and upload the folder as a pull request to the datastore.

pip install -U huggingface_hub
hf auth login
hf upload {{hf_repo}} my_submission/{{data_dir}} {{data_dir}} --repo-type dataset --create-pr --commit-message "Add EvalSpec records: <model or paper>"

Without the command line: open the datastore on Hugging Face, choose Contribute and then Upload files, and select the option to open a pull request before you commit.

What happens next

  • A maintainer runs the same validator on the pull request. A record has to be well formed. It does not have to reach a tier.
  • After the merge the site is rebuilt from the datastore. The record appears in the registry and on the page of its model, in the track its provenance tag puts it in.
  • A record is corrected or withdrawn with another pull request.

Emit records from a run

A harness holds the whole configuration at the moment it computes a score. The released hook for lm-evaluation-harness reads it from the objects the harness returns and writes one flat record per task. It is lm_eval_to_evalspec.py in the code repository.

import json
from lm_eval import simple_evaluate
from emission_hooks.lm_eval_to_evalspec import emit_evalspec

out = simple_evaluate(model=lm, tasks=["gsm8k"], num_fewshot=5)
records = emit_evalspec(out, model_args={"pretrained": "meta-llama/Llama-3.1-8B"})
with open("records.json", "w") as f:
    json.dump(records, f, indent=2)

As released, the hook leaves out benchmark_variant, answer_parser_version for generation tasks, and the range of the score (min_score, max_score). Its prompt hash covers the task template only. Add what is missing to each record; the validator lists it.

The validator is one Python file without dependencies. Download evalspec.py and fields.json into one folder.

python evalspec.py check records.json --verbose          # tier, coverage and what is missing
python evalspec.py to-eee records.json --output my_submission/   # writes my_submission/{{data_dir}}/<source>/<developer>/<model>/<uuid>.json
python evalspec.py hash prompt.txt                        # sha256 of a prompt template

For another harness, an adapter maps its configuration keys onto the same flat record. The Spec page lists what HELM, LightEval and OpenCompass already expose.

Upload predicted records

Many published scores will not be reported again by their authors, so records read from a publication by a language model are part of the datastore. They are uploaded by a person, who answers for them, and they are listed as predicted. In the paper's audit, 97.5% of the scores extracted from ten papers matched the publication. Where a paper attributes a harness to a result, the extractor named it in 71.5% of the cases and never named a wrong one.

  • Set evidence_source to LLM-extracted, and name the model in extractor_model.
  • Where a value was not read from the publication but added from documentation or a default, tag that field on its own.
  • Leave out what the publication does not state. A missing field is shown as not on record; a guessed one would be shown as if it were known.
  • evaluation_timestamp is the time of the evaluation. The day the publication was read goes in extraction_date.
  • Give the title of the publication in source_name and its address in source_url.

If a predicted record describes your result

Find the model in the registry, open the record and choose Correct this record. The form above opens with the predicted values. Change what is wrong, add what only you know, keep the first answer under Who is filling this in, and submit the result as a new record. Both stay in the datastore, and the author-reported one is listed first.
